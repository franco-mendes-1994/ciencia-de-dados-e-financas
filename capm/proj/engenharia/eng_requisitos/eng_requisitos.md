## 1. Elicitação de requisitos

O que o software faz (não "como" ele faz). Entretanto, isso deve ser informado de forma discriminada, por exemplo, o programa deve ler os dados de preços de ações do setor petroleiro listados na bolsa brasileira.

É fundamental descrever bem os requisitos, pois normalmente isto está definido em contrato. Segundo o Nelson, o que é considerado qualidade em engenharia é o cumprimento dos padrões estabelecidos no contrato.
